## Verdict

**BLOCK.** Keep #10557 open and retain the current exception policy until the Core Team resolves the ownership question and a replacement design preserves cron admission across both shell and agent jobs.

## Findings

1. **Blocking — The governance change needs an RFC.** REPORT lines 7–14 and PLAN lines 103–114 treat permanent residency as already ratified. FND-001 line 612 does assign the agent loop, security policy, plugin host and IPC API to the runtime **in Phase 2**. The same paragraph excludes knowledge of specific tool implementations. Line 660 lists eleven built-in tools, and line 690 assigns the Phase 3 IPC server to `zeroclaw-kernel`. None grants permanent residency to today’s entire `tools`, `security`, or `rpc` trees. The runtime contract explicitly names the agent loop, security and skills for extraction. The composition contract still names a future kernel owner. Option C is a defensible proposal, but PR 0a cannot establish it through ordinary documentation review. FND-003 requires an RFC for governance and cross-boundary ownership changes, with a recorded snapshot, vote and quorum. [FND-001](../../../docs/book/src/foundations/fnd-001-intentional-architecture.md#phase-2-deliverables) · [Runtime contract](../../../crates/zeroclaw-runtime/AGENTS.md#L5) · [Composition contract](../../../docs/book/src/architecture/runtime-composition.md#L223) · [FND-003 §8](../../../docs/book/src/foundations/fnd-003-governance.md#L554)

2. **Blocking — PR 5 leaves an authorization boundary unspecified.** PLAN lines 220–240 says a `CronAgentExecutor` lets the scheduler stop naming admission types. The scheduler resolves ownership against selected and admitted config, revalidates admission before **shell** execution and retries, and retains it through delivery and history persistence. Moving agent execution alone cannot preserve that lifetime. Isolated-run failure also invokes capability-scoped memory cleanup. Specify who holds and revalidates admission for manual, scheduled, shell and agent paths before promising PR 6 as an unchanged move. PR 4’s proposed `platform` relocation is unnecessary for `create_runtime`, already owned by `zeroclaw_config::platform`. `SecurityPolicy` likewise comes from config. [Scheduler](../../../crates/zeroclaw-runtime/src/cron/scheduler.rs#L623), especially lines 867–893, 1074–1116, 1342–1357 and regression 4174 · [Platform owner](../../../crates/zeroclaw-config/src/platform/mod.rs#L13) · [Policy re-export](../../../crates/zeroclaw-runtime/src/security/policy.rs#L1)

5. **Major — The 42 references are a selected sum.** ARCHITECTURE lines 181–205 reproduces **42** for its chosen edges. The **25 helpers / 17 real calls** interpretation fails inspection. The 17 include error formatting, type mentions and memory acquisition. The 25 include actual tool construction (`sop/mod.rs:95`) and plugin host-service construction (`plugin_runtime.rs:1179`). Removing those 42 from the saved graph leaves four strongly connected groups, including SOP↔calendar and agent/composition/skills/tools. For the proposed crate boundaries, cron and SOP still reference resident live-config authority **3 and 7** times. Quickstart also uses it, skills calls the agent loop, and security and live-config authority both need i18n. `modgraph2.py:450–470,534–559` scans undeclared files, collects glob mappings without resolving them, and combines feature configurations. Runtime `platform/mod.rs:1` only re-exports config in production, yet the graph charges it 313 production lines. Test stripping also counts eight newlines for the nine-line test-only item at `observability/otel_config.rs:15–23`. The scanner is unsuitable as the sole CI dependency gate.

6. **Major — The conflict experiment proves less than “stays mergeable.”** PLAN lines 49–99 accurately transcribes the JSON. `simmove.py:52–78` preserves the module directory but strips self-paths and introduces upward `zeroclaw_runtime` references in its rewritten variant, including tests and comments. It omits necessary manifest, caller and registration edits. Its source-path filter misses destination-only changes and downstream compile failures. Thirteen snapshot PRs target branches other than master. Two saved GitHub-mergeable PRs, #9245 and #11596, already conflict against the simulator’s master baseline. Git’s `merge.directoryRenames` defaults to `conflict` and also supports automatic relocation or leaving files behind. GitHub parity was assumed. REPORT line 30 also overlooks #12553’s conflict in the **moved** providers redaction file.
